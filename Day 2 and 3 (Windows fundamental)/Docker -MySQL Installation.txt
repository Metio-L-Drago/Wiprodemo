PHASE 1: Docker Installation on Ubuntu (Production-Safe Method)

Works on Ubuntu 20.04 / 22.04 / 24.04

1️⃣ Update the system (always first)
sudo apt update
sudo apt upgrade -y


Why?
Ensures security patches and dependency compatibility before installing Docker.

2️⃣ Install prerequisite packages
sudo apt install -y ca-certificates curl gnupg lsb-release


What these do (important):

ca-certificates → Secure HTTPS downloads

curl → Download Docker GPG key

gnupg → Verify package authenticity

lsb-release → Identify Ubuntu version

3️⃣ Add Docker’s official GPG key
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg


Enterprise reason:
Prevents tampered or fake Docker packages.

4️⃣ Add Docker repository
echo \
"deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://download.docker.com/linux/ubuntu \
$(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

5️⃣ Install Docker Engine
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

6️⃣ Verify Docker installation
docker --version


Expected output (example):

Docker version 26.x.x

7️⃣ Start and enable Docker service
sudo systemctl start docker
sudo systemctl enable docker


Check status:

systemctl status docker

8️⃣ Allow non-root Docker usage (VERY IMPORTANT)
sudo usermod -aG docker $USER


Then logout & login again.

Verify:

docker run hello-world


If this runs → Docker is correctly installed ✅

PHASE 2: MySQL Deployment Using Docker (Enterprise Method)

We will use:

Official MySQL image

Persistent storage

Named container

Environment variables

9️⃣ Pull MySQL image
docker pull mysql:8.0


Why MySQL 8?
Industry default, security patches, InnoDB improvements.

🔟 Create a Docker volume (Persistent Storage)
docker volume create mysql_data


Check:

docker volume ls


Why volume is critical:

Data survives container restart

Matches real production behavior

1️⃣1️⃣ Run MySQL container (Production-Style)
docker run -d \
--name mysql-db \
-p 3306:3306 \
-v mysql_data:/var/lib/mysql \
-e MYSQL_ROOT_PASSWORD=Root@123 \
-e MYSQL_DATABASE=companydb \
-e MYSQL_USER=appuser \
-e MYSQL_PASSWORD=App@123 \
mysql:8.0

🔍 What each option means (do not skip)
Option	Purpose
-d	Run in background
--name	Fixed container name
-p 3306:3306	Expose MySQL port
-v mysql_data:/var/lib/mysql	Persistent DB storage
MYSQL_ROOT_PASSWORD	Root password
MYSQL_DATABASE	Auto-create database
MYSQL_USER	Application user
MYSQL_PASSWORD	App user password
1️⃣2️⃣ Verify MySQL container is running
docker ps


Expected:

mysql-db   mysql:8.0   Up

PHASE 3: Access MySQL Inside Docker
1️⃣3️⃣ Enter MySQL container shell
docker exec -it mysql-db mysql -u root -p


Enter password:

Root@123

1️⃣4️⃣ Validate database and user

Inside MySQL prompt:

SHOW DATABASES;


You should see:

companydb


Check users:

SELECT user, host FROM mysql.user;

1️⃣5️⃣ Test application user login

Exit root:

exit;


Login as app user:

docker exec -it mysql-db mysql -u appuser -p


Password:

App@123

PHASE 4: Operational Commands (Real-World Use)
Stop MySQL container
docker stop mysql-db

Start MySQL container
docker start mysql-db

Restart MySQL container
docker restart mysql-db

View MySQL logs
docker logs mysql-db

PHASE 5: Important Enterprise Notes (Trainer Explanation)
❗ Why Docker MySQL is used in companies

Fast environment setup

Identical dev → test → prod behavior

Easy rollback

Infrastructure as Code

❗ Why volumes matter

Without volumes → data loss on container deletion
With volumes → production-safe

COMMON INTERVIEW QUESTIONS (VIVA READY)
Q1. Does Docker replace MySQL?

❌ No. Docker runs MySQL, it doesn’t replace it.

Q2. Where is MySQL data stored?

✔ Inside Docker volume mounted to /var/lib/mysql

Q3. What happens if container is deleted?

✔ Data remains (volume persists)

Q4. Why not install MySQL directly?

✔ Docker gives portability, isolation, consistency
